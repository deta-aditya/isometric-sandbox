# Agent notes

Read this first. It replaces exploring the code to learn how things fit together.

## The project

An isometric sandbox for building a school campus (walls, floors, furniture, roads, water). PixiJS v8 + TypeScript + Vite, no framework. Published as a claude.ai artifact. The owner (Deta) is a senior TypeScript engineer who prefers functional programming and immutable data. Plans live in `Todos.md` (also the project doc "Todos"); what players see as new lives in `CHANGELOG.md` (also the project doc "claude/Changelog").

## Rules for any change

- **Functional core, imperative shell.** Core files are pure: no Pixi, no DOM, no mutation. Everything returns new readonly data.
- **Every world change goes through `update(state, action)`** in `world.ts`, wrapped by `history.ts` for undo. Never mutate state in the shell.
- **One user action is one undo step.** History records only the world (`objects`, `tiles`, `walls`, `culverts`, `nextId`). UI state (tool, tray, camera, filters, clipboard, blueprints, guides) is never undone.
- **View space.** The world is stored unturned. `view.ts` turns the state into the camera's view (`toView`), `update` runs there, then it is turned back (`fromView`). So all rules are written for one camera direction and work from all four. Anything new in state that has a position or direction needs a case in `view.ts`.
- **Write user-facing text without em dashes.** That includes labels, help, chip text and docs.
- **Text must fit.** Any HUD or label change runs the UI sweep (`./check.sh --ui`).
- **Keep files' style.** Small pure helpers, `Readonly<...>` types, discriminated unions, short comments explaining why, not what.

## Things that are easy to get wrong

- **Flat ground pieces** (roads, markings) live in layers `road`, `marking`, `median` (`layerOf`). They collide only within their own layer; standing objects and walls ignore them. Click picking order: standing, median, marking, road.
- **Road widths (#31, #31b).** `WIDE` 5 (wide roads, group `roads`), `NARROW` 3 (medium roads: renamed, ids still `narrow-*`/`link-*`, group `narrow`, which also holds their links to wide) and `SMALL` 2 (narrow roads `small-*` plus their links to medium and wide, group `small`; dirt roads `dirt-*`, group `dirtroad`, with Dirt to paved). Bus bay pieces are group `busbay`. `laneLines(SMALL)` is empty, so the paved helpers (`straight`, `curve`, `junction`, `roadEnd`, `turnTransition(from, to)`) draw narrow roads with edge lines only. Dirt pieces come from `DIRT_BANDS` and `dirtJunction`. `straightAt` (junction snapping) takes straights 2 wide and up, not the bus bay middle. Arrows may not touch a `dirtroad` piece (`onDirt` in `canPlaceObject`). Chip titles must fit at 360px: about 16 characters.
- **Lane arrows (#40).** Arrow defs carry `arrow` (kind) and road straights carry `lanes` (`'wide' | 'medium' | 'narrow'`; a narrow road's two lanes meet in its middle with no line). `arrowLook` in `src/arrows.ts` (pure) picks the paint and the slide across the row from the road pieces under the arrow; `drawables.ts` adds it to flat drawables and `marksOf(def, r, paint, shift)` draws `arrowMarks(kind, paint)`. The def's own `marks` are the off-road look (tray icons). `snapArrow` moves an arrow placed on a narrow road's middle row into the lane on the pointer's side. Lane middles come from `laneSpans`.
- **Clipboard (#37).** Ctrl + C copies the marks and holds the copy at once (`paste` right after `copyOf`); Ctrl + X removes the marks (one undo step) and holds them; Ctrl + V holds the clipboard again any time. Copying while a group is held only keeps a copy. A held copy stays in hand for every click until Esc.
- **Placement of objects** goes through `buildPlan` (which may replace road pieces). Paste, blueprints and group drops use the strict `canPlaceObject`.
- **Drags** (`state.drag`) have modes; painting drags fill gaps with `cellsBetween`. A drag is one undo step.
- **Rotation** (R) belongs to the world and persists across item picks.
- **Map size** is `State.size` (a `Size` from `sizeOf(w, h)`, one object per size, so compare sizes by identity). In a view the state's size is that view's frame: on a non-square map width and height swap on odd views. Bounds helpers take the size (`cellInBounds(s.size, c)`), and so do `interiorCells` and `canopyCells`. `pointToView`/`pointFromView` take the world size; `guideFromView` takes the view's frame.
- **Terrain** is its own layer (`State.terrain`, one per cell, none means grass), under floors and above the grass fill. Its look is not per-tile shapes: `terrainField.ts` blends terrains by weight, so there is no stacking order and no halo. Tune the blend with `SIGMA` and `REACH` (how far a tile's color spreads) and the 1.5 power on the weights (sharpness). Each map has a ground (`State.ground`); `terrain` holds only tiles that differ from it. Filters are in `FILTER_ORDER` (catalog.ts), not `CATEGORIES` order, so Terrain is key 5 while the bar shows it after Flooring.
- **Sunken water (#17).** The canal's water lies `CANAL_DEPTH` below the ground. Anything drawn below ground goes into the masked canal layer in scene.ts (the mask is the canal tiles at ground level), never straight onto a layer, or it will hang past the canal's banks. The stream is part of the ground picture (`terrainField.ts`): a field of its tiles plus a slow wobble gives a depth, and each pixel shows the lowered point that appears there (a surface z px down shows z / TILE_H tiles along +x and +y). Floating items (`floats` in catalog.ts) get a `sink` offset in drawables. Tray icons and blueprint cards draw water with the same code through `waterLayers` (water.ts); `toDataUrl` takes the layers a drawing hands back.
- **Canal joints and stream stonework (#17c).** A culvert edge may carry `kind: 'outlet' | 'inlet'` (`CulvertEdge`): those pieces only fit an edge between a canal tile and a stream tile (`canalStreamOf`), drag along the joint, and keep their kind through turns, saves, copy and the picker. Since #17f the stream tile at a joint is lined with stone (`drawJointSunk` in its own masked layer, `jointBox` in scene.ts; coping and posts in `drawJointTops`): its walls carry the canal's walls on, flush, and a run shares them (walls only at the run's `start`/`end`). The water falls across the joint toward the low side (outlet: canal at `CANAL_DEPTH` into the stream at `STREAM_DEPTH`; inlet: the stream raised to `INLET_RAISE` falls into the canal); the falling face shows only when the low side is nearer the camera, foam always shows on the low side, and with the stream behind the canal's layer draws the lined water first so it shows past the lip. Terrain: joints pin the joint side and walled sides, add a `pool`, and an inlet adds `raise`, which lowers the stream less within two tiles so it rises to the inlet. Joints "pin" the stream tile's side (`streamPins` in terrainLayer.ts, `pins` in `TerrainGrid`): the water reaches straight up to the stone with no wobble, and the ground on the other side of the stone stays level, so a near-side wall is not covered by the lowered water behind it.
- **Culvert pieces (#17d).** A plain culvert is still stored as its bank edge, but it is drawn as stonework on the water tile behind it: a back wall along the edge plus a side wall at either end where the tile beside it is not water (`culvertShape` in world.ts: a U on a 1-wide channel, Ls at a wide end's corners, the back wall alone in between). It fits only across a channel's end (`atChannelEnd`: the water runs on into the channel at least as far as the end is wide). Below-ground faces and pipe mouths go into the masked canal layer (the mask gets the piece's tile and the water in front of it, for streams too); tops go on top. On a stream the piece pins its walled sides and adds a `pool` pin: the water is deep across the tile and eases back over a tile and a half, on stream tiles only and away from land. Side walls slope: their tops fall from the back wall's height (`RISE`) at the corner to `RISE_END` at the open end.
- **Stream sharpness (#17e).** Chunks with a stream near are drawn at `STREAM_PX` (16 per tile; others stay at `TERRAIN_PX`, 8): the terrain blend is still worked out at 8 and read smoothly, the stream's depth field is worked out at 16 with a two-pass blur. `chunkPx` gives a chunk's size, so stream tests index pixels with `STREAM_PX`. The water starts with a clear edge (no wet-earth fade) and darkens only a little toward the middle; the lowering step is damped (8 steps at 0.6) so steep banks do not go jagged, and against far-side stone the water is held one coarse pixel in so it reaches the stone. The waterline blends over about a pixel, and pixels where water meets bank (the near bank's fold) are taken again as four averaged samples, so neither bank is a staircase. The grid's stream mask also covers the tiles as lowered, so grid lines do not cross the water at near banks.
- **Courts (#33).** Sports court markings are flat pieces in the marking layer (group `courts`, Flooring > Courts): white lines only, so they go over any floor, path or plain grass (markings never needed a road under them; they only keep clear of their own layer). The court is 12 by 6 tiles regardless of real size: lengths scale by `CX`, widths by `CY`, circles by `CR` (`courtEnd`, `courtOutline` in catalog.ts). The hoop is a 1 by 2 object (Scenery > Sports) so it sits on the 6-deep court's center line. The mini soccer court (#34) is the same 12 by 6 (`soccerEnd`, lines scaled by `SK`), and its goal is also 1 by 2; nets are drawn as thin strands (`NET`), never solid panels, which read as a walled pen. The tennis court (#35) is 12 by 6 as well, with a 2 by 6 Tennis net whose band lies on the footprint's middle (x = 1) so it stays on the court's middle line after turning; a single thin net plane may be solid (only a box of solid panels reads as a pen). Court yellow joins the court floors. Court surfaces are ordinary floors in the Floors tab, their colors picked by measured Lab distance from every tile and terrain color (keep doing this for new floors). A tile may have a `stripe` color: every other world column takes it (`worldColumn` in scene.ts turns the drawn cell back to the world), so mowed stripes keep their direction as the camera turns.
- **Floor textures and diagonal paths (#11).** `src/render/floors.ts` turns floor tiles into pieces (pure, tested in tests/textures.test.ts): each piece is a convex outline in its world tile with marks clipped to it. Patterns live in `src/render/patterns.ts`, drawn in the tile's world frame and varied only by a hash of the world tile, so they look the same from every side; a floor without a pattern that is not a path is plain (`isPlain`, one square, the fast path). `src/render/diagonals.ts` gives paths (group `paths`) 45 degree edges: corners cut on diagonal runs and single jogs, triangles in the bare tiles beside them; lone tiles, path ends, right-angle turns and plazas stay square, and only one path type joins itself. `BLENDS_INTO_GROUND` (Dirt path) grows a grass fringe on open edges and outlines them with the lawn's `GRID_LINE`. The scene draws floors in 16 by 16 chunks (a Container of Graphics) and redraws only chunks within 2 tiles of a changed cell; a new view, size, grid alpha or culverts start over. Wall paint textures are #11b. Patterns that must run on across tile edges (Crazy paving stones, Leafy dirt leaves) are generated from a world lattice or from the neighboring tiles too, and clipped to the piece when drawn (#45).
- **Running track kit (#32).** Track pieces (group `track`) are flat pieces in the `road` layer: `TRACK_W` 3 tiles across with `TRACK_LANES` 6 lanes of half a tile, curves of inner radius `TRACK_INNER` 4 (7 by 7, ring cells only), in `TRACK_RED` (the Running track tile's color). Start and Finish lines are markings. They are not roads: `isTrack` in world.ts keeps `straightAt` (junction snapping) off tracks, and `buildPlan` refuses a road piece over track or a track piece over road. Lane numbers come from `DIGITS` (3 by 5 block digits; `digitMarks` reads toward +x).
- **Room furniture tabs (#36, #42).** Furniture tabs sit by room (Office ... Kitchen, then Gym, Dorm, Laundry); keep each at 9 items or fewer so every item has a number key (keys 1 to 9 only; hotkeys are not settled yet, so do not add a 0 key without Deta). Standing objects face +y: their back is y = 0, and wall-mounted items (Wall hoop, Scoreboard, Wall shelf, Wall bars) hang on that edge, raised up the wall (`WALL_H` is 56). Round faces (the Washer's door) are thin stacked rows on the face. No bleachers: they will come from the platform kit (#44). Every new object must pass `tests/rotation.test.ts` (footprint and draw order in all four facings) and be looked at from all four camera sides.
- **Partial ground redraws (#17g).** When tiles change, the ground layer finds the box of changed tiles near each chunk (`changedBox`), widens it by `INFLUENCE` (4 tiles: the farthest a change can show) and redraws only that patch with `regionPixels`, pasted into the chunk's canvas. `regionPixels` gives exactly the pixels the whole chunk has there (tested), so patches leave no seams; a whole chunk is redrawn only when it is new or its pixels per tile change. To measure speed, profile with the CDP Profiler: headless Chromium draws frames in software, so wall-clock frame times there are mostly drawing, not the game's code.
- **Drawing only what is on screen.** `main.ts` keeps a drawn window (the screen plus half a screen around it) and `scene.render(seen, window)` builds, sorts and draws only what can show in it (`inWindow` in `drawables.ts`, which allows tall things below the window to reach into it). Anything new that is drawn per piece must go through that filter, or a big map gets slow again.
- **Saves** write the committed world (`history.committed` plus size and facing), never the state mid-drag. A change to what a save holds bumps the save version in `saveStore.ts` and adds an upgrade step so older saves still load.

## Checks

```bash
./check.sh          # typecheck + every test in tests/ + build. Prints only failures and one summary line.
./check.sh --ui     # also the text overflow sweep at 1280, 1101, 1024, 900, 700, 390, 360 px (needs a build)
```

Run `./check.sh` after every change and keep going until it says `ALL GREEN`. Do not paste passing output into reports.

**Tests** are plain scripts with `node:assert` in `tests/*.test.ts`, run with `cd tests && npx tsx name.test.ts`. They drive the game through `history.step` with real actions (hover, press, release, rotate, keys), so they test behavior, not internals. Copy the helpers at the top of an existing test (`roads.test.ts` is a good model: `click`, `drag`, `turns`). Add a test file or cases for every new behavior, including undo and all four camera views when positions are involved.

**Screenshots** (only when asked to check a look): Playwright in Python against `npx vite preview --port 4173`. Screen position of grid point (x, y) at default zoom on a 1280x720 page: `(640 + (x - y) * 22.4, 340 + (x + y - 64) * 11.2)`.

## Publishing (the lead agent does this, not helpers)

1. `./check.sh` is green (the build is in `dist/`).
2. `python3 tools/publish_plan.py` prints the slug, base version, files to send and files to remove.
3. Call the artifact `publish_files` tool with exactly that.
4. `python3 tools/publish_plan.py --record <new version>` with the version the publish returned.
5. Add a Done row to `Todos.md` and write it to the project doc "Todos".
6. Add the todo to "Waiting to be logged" in `CHANGELOG.md` (also the project doc "claude/Changelog"). Move it into the Log only when Deta says it is ready (it may be done but buggy, or not as wished): a short player-facing entry under that day's date, with the todo numbers. Write both docs after every change.

## Working as a helper

You get a spec from the lead agent. Build exactly that; if the spec is unclear or conflicts with the code, stop and say so instead of guessing. Report back in a few lines: what changed (files and functions), tests added, `check.sh` result, and anything you were unsure about. Do not publish, and do not edit `Todos.md`.
